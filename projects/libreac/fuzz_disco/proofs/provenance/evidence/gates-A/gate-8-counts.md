# Gate 8 — every image-derived count of lib/A recomputed from image A (fuzz_disco.asan)

Kind: measurement; proves no function. A relocated proof file can keep a COUNT of the donor image (cgif_file_fuzzer.asan):
a word count, a table length, a range length, a region count, a size. Gate 7 (roundconst v2) cannot see such a count when
its value is also a right quantity of the target, nor function sizes, nor an unnamed run (its README gaps 1-3). This
gate finds every count of `lib/A/**.v` by fixed text patterns, gives each a rule that derives it from an image, applies
the rule to the A pin and its unstripped twin (and to cgif's pin and twin, so the rule is shown to reproduce the donor's
own count), and compares with the shipped value.

## Command (run.sh `counts`)

```
count_recompute.py --lib $LIB --pin $PIN_A --twin $TWIN_A --cgif-lib $CGIF_LIB \
  --cgif-pin $CGIF_BIN.asan --cgif-twin $CGIF_TWINS/cgif_file_fuzzer.asan --out $OUT/counts/counts-A.tsv \
  --ruling KEY=TEXT ... (the three rulings below)
```

`counts/count_recompute.py` (script of record, copied) states its patterns and rules in its docstring. The twin is checked
against its pin before use (PT_LOAD table equal, PT_LOAD 2..4 bytes equal: true for both images). The output table
`counts/counts-A.tsv` (one row per count: key, name / call, shipped, rule with its values, recomputed, donor shipped,
donor recomputed, status, note, ruling) is regenerated byte for byte by run.sh (`counts/cmp`).

## Method

- Patterns, each match one count: P1 `build_table SEGS PC N%nat`; P2 `(PC, N%nat)` code ranges; P3 a `Definition COUNT :
  nat` a `build_table` names; P4 definitions named `*_len / _cnt / _count / _size / _bytes / _pad / _entries / _words /
  _n / _num / nslots / TEXT_N`; P5 record fields `*len / num / ent / res / count / size := N`; P6 `seg LIST I N`; P7
  `firstn / skipn N`; P8 `length EXPR op N`; P9 extents (`mkRegion None LO (LO + N)`, `mkChunk ADDR (CImg N)`, read-only
  cell tables `(ADDR, N, [`). 994 files of `lib/A` scanned; 395 pair with a cgif file by path.
- Code ranges are read on the twin's function symbols: `.text size / 4`; `(.text end − PC) / 4`; the donor's range read
  on cgif's twin as "function S + s to function E + e" and moved to this image by function name; with no donor range,
  whole functions, or a prefix through the function's first exit.
- Definitions by name (start / end / object addresses from the twin, the RW segment length, `e_phnum`, `e_phentsize`, a
  function's `st_size`); image-region slices and lengths by the region list of `AD2j.v` (80 regions here, 33 in cgif);
  string lengths by `strlen` in the pin; the trace depth by AF0m's `malloc_context_size` cell.
- A count that is no image quantity is NOT-IMAGE with what it counts and a check where one is cheap (e.g. AB01's
  `seg` slices: I + N ≤ the sliced state list's length, computed from the file).

### The TRUE row

`A/AE3h.v:1724` x13_ranges `(0x70504, 12%nat)`: MEASURED TRUE: exact function cover; the donor's +1 word not taken.
Rule `twin FUNC __sanitizer_cov_dump st_size / 4` = 48 / 4 = 12. cgif ships 13 = its own exact cover plus the first
word of `__sanitizer_dump_coverage` (the donor's over-cover). The unit owner's rule: an over-cover carried from the
donor is a defect, fixed to the measured value; an exact cover that differs only from the donor's over-cover is true.
